# DWH → HJ Track: покрытие пульсометрами

Ночной скрипт считает в аналитике (DWH) «покрытие пульсометрами» по клубам и
пишет снапшот в Firestore (`hrm_coverage/{КЛУБ}`). Приложение HJ Track показывает
его в разделе **Пульсометры → Без пульсометра** (менеджеру — его клуб).

## Метрика (метод как у коллег)
- **Активный ХП** — участники с действующим Hero Pass (`ods_core.userheropass`,
  `end_time >= сегодня`, не `refunded`), по клубу абонемента.
- **С пульсометром** — носили монитор за последние `windowDays` дней
  (есть запись пульса в `main.summaryheartrates`).
- **Без пульсометра** — активный ХП, но недавно монитор не носили.

## Установка (один раз, на ноуте Sales5)
```
cd dwh-sync
npm install
copy config.example.json config.json
```
Затем открой `config.json` и впиши **read-only** строку подключения к DWH:
```json
{ "dwhUrl": "postgresql://user:pass@host:5432/db", "windowDays": 21, "ssl": true }
```
`windowDays` — окно «недавно» (подгони, чтобы совпасть с цифрой коллег: у них ≈ 2060 / 20.5%).

## Проверка
```
node hrm-sync.mjs
```
В консоли — по клубам «активн/с/без». В приложении данные появятся сразу.

## Автозапуск (раз в 6 часов)
Запусти `start-hrm-sync.bat` (крутит скрипт в цикле, как WhatsApp-мост).
Для скрытого окна можно добавить `.vbs`-обёртку, как у мостов.

## Требуется от команды DWH
Read-only доступ к `ods_core.userheropass` и `main.summaryheartrates`
(+ сетевая доступность хоста DWH с ноутбука Sales5).
